**最终结果：**

内核启动时，控制权交给汇编入口 kern_entry，入口代码先建立内核栈，再进入初始化函数：

````markdown
kern_entry:
    la sp, bootstacktop
    tail kern_init
````

la 是加载地址的伪指令，将符号 bootstacktop 的地址写入栈指针寄存器 sp，并不是读取该地址中的数据。
文件末尾预留了启动栈空间：
````markdown
bootstack:
    .space KSTACKSIZE
bootstacktop:
````
其中 bootstack 是这段空间的低地址起点，bootstacktop 是高地址端。由于 RISC-V 的栈向低地址增长，因此把 sp 设置为 bootstacktop，就建立了一个初始为空的内核栈。
这为后续 C 函数执行提供有效的栈空间，用于保存局部变量、寄存器和函数调用信息

tail kern_init完成的操作是,跳转到 kern_init函数，但不会像call 那样把返回地址写入 ra. tail 是尾调用伪指令

本实验的 kern_init 声明为 no return，最后进入无限循环，因此不需要返回 kern_entry，使用 tail 正好符合
